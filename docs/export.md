# PDF export

Three on-demand PDF exports, all rendered locally with Pillow — no external service. Output lands in `data/exports/<filename>.pdf` and is streamed back to the browser as `application/pdf`.

Implementation in [`services/export.py`](../backend/src/card_tracker/services/export.py); endpoints in [`api/cards.py`](../backend/src/card_tracker/api/cards.py) and [`api/binders.py`](../backend/src/card_tracker/api/binders.py).

## The three exports

| Export | Endpoint | Format | When to use |
|---|---|---|---|
| **Whole collection** | `GET /api/cards/export.pdf` | Row-style: thumbnail + name/set/number/year/type/notes, paginated. | Share the full database — printable index, Discord drop, backup snapshot. |
| **Binder cards** | `GET /api/binders/{binder_id}/export-cards.pdf` | Same row-style, restricted to the cards linked to placements in this binder. | "Here's everything that's in my Sports 1 binder." |
| **Binder pages** | `GET /api/binders/{binder_id}/export-pages.pdf` | One PDF page per binder page; the binder's RxC layout drawn full-grid with each card's crop in the right slot. | Visual catalog of the physical binder — pocket-by-pocket, in order. |

All three are GETs so they work as plain `<a href download>` links. Each call regenerates from the current DB state — no caching.

## Page layout (row-style)

Constants in `export.py`:

- **Page size**: 1240×1754 px (150 DPI A4, portrait — kept portrait deliberately; cards are 63:88 tall, landscape would waste vertical space).
- **Header**: title + `N cards · YYYY-MM-DD · X pokémon · Y sports · Z other`.
- **Rows**: rounded panel per card, 220×307 px thumbnail (63:88 trading-card ratio), then name (28 pt bold), `set · #number · year` line, type badge, optional notes line. Long fields are ellipsis-truncated to fit the column.
- **Footer**: `Generated by 10pow6 Card Tracker` left, `Page X / N` right.
- **Pagination**: `ROWS_PER_PAGE` is computed from the layout constants — typically ~4 rows/page at the current sizes.

Thumbnails are pulled from `core_card.representative_crop_path`. Missing or unreadable crops render a `no image` placeholder rather than failing the page.

## Page layout (binder pages)

Same page size and chrome, but the body is an RxC grid sized to the binder's layout. Each cell:

- Largest 63:88 card that fits with caption space reserved (`_fit_card_size`).
- Crop loaded from the placement's `crop_image_path`, rounded corners.
- Empty / unmatched slots render an outlined panel with `empty` centered.
- Caption underneath: bold name + `set · #number · year` subtitle, both ellipsis-truncated to cell width.

## Card ordering

Both row-style exports sort:

```sql
ORDER BY
  CASE WHEN name IS NULL THEN 1 ELSE 0 END,   -- named cards first
  LOWER(COALESCE(name, '')),
  LOWER(COALESCE(set_name, '')),
  card_number,
  created_at
```

So named-and-enriched cards lead the document, unenriched cards trail at the back.

The binder-pages export is ordered by `page.page_number ASC`, then `placement.slot_index ASC` within a page — i.e. the same order you'd see flipping the physical binder.

## Filename convention

```
data/exports/collection-YYYYMMDD-HHMMSS.pdf
data/exports/<binder-name-slug>-cards-YYYYMMDD-HHMMSS.pdf
data/exports/<binder-name-slug>-pages-YYYYMMDD-HHMMSS.pdf
```

The slug strips non-alphanumerics and lowercases (`Sports 1` → `sports-1`). Timestamp is UTC.

## Fonts

Cross-platform best-effort loader (`_font`): tries Arial (Windows/macOS) and DejaVu Sans (Linux), falling back to PIL's bundled bitmap font if none of those resolve. The bitmap fallback is ugly but the export still completes — useful in stripped containers.

## Why Pillow PDF (not ReportLab / WeasyPrint)

The renderer composes one `PIL.Image` per page and saves them as `pages[0].save(out, save_all=True, append_images=pages[1:], format="PDF")`. Pillow encodes each page as a JPEG inside the PDF — typical row-style page comes out ~10–20 KB. No HTML/CSS pipeline, no headless Chrome, no extra Python dep beyond Pillow which we already use for crops. Raster, not vector — fine for our use case (sharing visual catalogs, not typesetting); fonts and thumbs are drawn into pixels.

## Where the UI exposes them

- **Catalog (`/cards`)** → **Export PDF** button → whole collection.
- **Binder detail (`/binders/:id`)** → menu / button → both `export-cards` and `export-pages`.

Both render synchronously — for a few hundred cards the round-trip is sub-second; tens of thousands of cards is on the order of seconds and runs in the request thread.
